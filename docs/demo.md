# Демонстрация за несколько минут

1. `npm run dev`, открыть http://127.0.0.1:5173.
2. Оставить Synthetic demo / Demo power curve, запустить 48 часов. Показать 96 точек, DEMO, предупреждения о высоте ветра и журнал агента.
3. Скачать CSV. Проверить обновление входов: при неизменных данных повторный прогноз не создаётся.
4. Раскрыть Datasets & model training, импортировать `examples/observations.demo.csv`, включив Synthetic dataset и указав происхождение. Обучить Binned power curve с cutoff 30.01.2026 23:00 UTC. Она остаётся DEMO и появляется в селекторе прогноза.
5. Вернуться к прогнозу, выбрать модель. Запустить replay с preset февраля. Метрики отсутствуют без фактов, покрытие показано явно.
6. В Weather archive показать статусы снимков. Archive без проверенных снимков возвращает ошибку доступности. На карте показаны подтверждённые координаты, номинал и высота ступицы остаются незаданными.
7. Если заранее выполнена валидация реальной SCADA, показать `artifacts/validation.json` отдельно от synthetic replay. В отчёте указаны cutoff, покрытие и метрики persistence; погодные модели требуют проверенного архива.

Автоматизированная проверка HTTP через frontend proxy: `uv run python scripts/smoke_demo.py` при запущенном `npm run dev`. Проверяются 48-часовой прогноз, неизменность входов, 29 ежедневных выпусков и февральский CSV. Для отдельного API: `uv run python scripts/smoke_demo.py --api http://127.0.0.1:8000`.

Что не заявляем: что погодный hindcast доказывает историческую доступность; что synthetic прогноз имеет конкурсную точность; что есть факты за февраль; что квантили калиброваны; что нормализованная мощность известна в MW.

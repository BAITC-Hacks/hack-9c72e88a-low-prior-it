# Frontend

React + TypeScript + Vite. Запуск — `npm run dev:web`, сборка — `npm run build`. Весь HTTP-клиент находится в `frontend/src/api.ts`; типы импортируются только из сгенерированного `src/generated/api.ts`.

Три раздела: прогноз/replay; данные/модели; погода/координаты. Доступны выбор турбин, время выпуска UTC, 24/48 часа, demo/archive, модель, опрос заданий раз в 1.5 секунды, график/таблица, actual overlay, CSV, журнал решений и история. При ошибке показывается сообщение API; polling останавливается при terminal status и при ошибке запроса. «Обновить» перечитывает списки, выбор записи истории повторно запускает polling для активного задания.

Canonical CSV разбирается Papa Parse; JSON соответствует DatasetImport целиком. Demo checkbox и provenance для CSV явные; JSON содержит собственные поля. Нормализация, преобразование времени и расчёт мощности в браузере не выполняются. Среднее по отображаемым прогнозам подписано как среднее по турбинам/часам, не как мощность всей станции в MW.

Все времена интерфейса — UTC независимо от часового пояса компьютера. Preset 07:00 UTC — решение команды. По SCADA это 13:00 при постоянном UTC+6. Для окна февраля по шкале SCADA вместо UTC задайте начало `2026-01-31T18:00` и конец `2026-02-28T18:00`; это меняет только target-фильтр, а не определение горизонта T+1…48.

Карта-схема показывает подтверждённые координаты с локальной метрической проекцией; ссылки открывают OpenStreetMap. Номинал и высота ступицы остаются незаданными. Снимки погоды показывают original run, publication и verification; JSON редактор позволяет импортировать новую ревизию после проверки источника.

Vite проксирует `/api` и `/health` к 8000. Production `frontend/dist` требует HTTP-хостинга с тем же proxy. UI не обращается к погодным API и не хранит ключи. Все формы доступны с клавиатуры; мобильные блоки складываются в одну колонку. Автоматическая сборка проверена; визуальную проверку в текущей среде нужно выполнить вручную, поскольку управляемый браузер недоступен.

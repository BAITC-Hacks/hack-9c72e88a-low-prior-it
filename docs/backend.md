# Backend, модели и хранение

FastAPI запускается одним процессом на 127.0.0.1:8000. `/docs` — интерактивная схема. Все бизнес-маршруты имеют префикс `/api/v1`. JSON ошибок: `{code, message}`. Задания возвращают HTTP 202 и проходят queued → running → succeeded/failed. Подготовка прогноза (проверка модели и архива) синхронна: недопустимые входы отклоняются до постановки задания.

`routes.py` отвечает за HTTP; `service.py` связывает компоненты; `storage.py` хранит JSON-записи в SQLite с WAL и блокировкой соединения. Данные, модели и погодные снимки неизменяемы; обновлять можно только состояние заданий. При запуске незавершённые задания помечаются `process_restarted`. Очередь внутрипроцессная; несколько API workers не поддерживаются.

## Модели

| ID/алгоритм | Поведение | Ограничение |
|---|---|---|
| demo-power-curve | Иллюстративная кубическая кривая | Всегда DEMO, не обучается |
| binned-curve | Медианы по бинам 0.5 м/с, монотонная интерполяция | Ветер SCADA отличается от ветра NWP на 100 м |
| persistence | Последняя мощность, доступная к issue time | Без знания изменения ветра |
| weather-ridge | Ridge-регрессия, L2=10 | Кандидат; требуется хронологическая проверка |

Все обучающие строки удовлетворяют `valid_time <= trained_through` и `available_at <= trained_through`. Модель запрещена для выпусков до своей даты отсечения. Артефакт — JSON с параметрами, версией, cutoff, fingerprint, ID набора и числом строк. Загрузка pickle не используется.

Ridge использует wind, wind², wind³, температуру, sin/cos направления, lead, sin/cos UTC-часа и последнюю доступную мощность. Масштабирование обучается только на тренировочных парах. Пары сохраняют issue/valid/turbine; issue равен опубликованному времени снимка, округлённому вверх до часа. Каждый target ограничен cutoff; последнее наблюдение ограничено issue и latency. Снимки нужны проверенные. Прогноз ridge явно ограничен [0,1], исходные наблюдения никогда не обрезаются. Неопределённость не выдаётся без калибровки.

Данные реальных турбин можно импортировать через `scripts/convert_scada.py`, затем `scripts/import_csv.py`. Остановка или ограничение выработки сохраняются в фактическом target. Старый анализ `windagent/scada.py` очищает их для оценки нормальной кривой; это другой набор и не используется для официальной оценки автоматически.

## Оценка

Replay сначала создаёт все прогнозы, затем читает факты. Метрики — MAE/RMSE отдельно по турбине и lead 1–24/25–48. Пропуски учитываются в `missing`, при отсутствии фактов метрики null. CSV хранит каждый issue/valid/turbine отдельно и фильтруется по target `[evaluation_start, evaluation_end)`. Фактические значения включены отдельной колонкой.

`scripts/validate_models.py` проверяет месяцы до февраля 2026. Persistence доступен без погоды; для кривой и ridge нужен `--snapshots verified.json`. Непокрытые issue/turbine пары выводятся явно. Числа разных моделей нельзя сравнивать без проверки одинакового покрытия.

## Проверки

`npm run contracts` генерирует OpenAPI и TypeScript. `npm run check` запускает lint, pytest, typecheck и production build. CI также проверяет drift схем и выполняет HTTP smoke через Vite. Для разработки изменения backend требуют перезапуска процесса.

Это локальное приложение без авторизации. Для размещения вне localhost необходимы аутентификация, лимиты запросов, производственная очередь, миграции и reverse proxy. Отдельные большие обучающие задания пока выполняются синхронно.

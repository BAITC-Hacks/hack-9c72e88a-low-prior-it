# Защита за три минуты

Показываем полный путь: выбранные турбины → архив погоды → CatBoost weather-SCADA
→ почасовая выработка → анализ агента → обновление входов → проверяемый экспорт.
Главный артефакт — [февральский прогноз](../results/february-2026/forecast.csv),
а качество оценивается отдельно на одинаковых январских парах пяти моделей.

**Ограничение:** это предварительная реконструкция по hindcast-архиву ECMWF.
Время публикации предполагается равным `run_init + 10 часов`; расписание
распространения не доказывает доступность каждого исторического прогноза.
Фактической выработки за февраль нет, поэтому февральские MAE/RMSE отсутствуют.

## Подготовка с чистого клона

Нужны Node.js 22.12+ и uv. До выступления выполнить из корня репозитория:

```sh
uv sync --locked
npm ci
npm run reproduce
npm run check
npm run dev
```

`reproduce` подготавливает исходные CSV, импортирует только ECMWF 00 UTC,
выбирает погодную модель по ноябрю/декабрю, оценивает январь, дообучает модель
и запускает февральский replay. Команда также регистрирует веса и снимки
в локальной базе API. В чистом клоне локальные веса создаются обучением;
наличие сохранённого отчёта Evidence само по себе не означает наличия весов.

Открыть http://127.0.0.1:5173. В другом терминале проверить реальный HTTP-путь:

```sh
uv run python scripts/smoke_demo.py --archive
```

Проверяются архивный прогноз двух турбин, журнал анализа, refresh при неизменных
входах, 29 ежедневных выпусков и CSV. Проверка интеграции не измеряет точность.
Вариант без `--archive` остаётся отдельной синтетической демонстрацией.

| 0:00–0:20 | Explore → Казахстан → ВЭС → обе турбины → Open forecast | Почасовая выработка отдельных турбин на 24–48 часов; другие типы энергетических объектов пока не имеют обученных моделей. |
| 0:20–0:55 | Выбрать зарегистрированный `catboost-weather-scada-v1`, архив, выпуск 31.01.2026 12:00 UTC и горизонт 48 часов → Run forecast | 96 точек используют погоду ECMWF и SCADA, доступную по принятому протоколу. Метка provisional сохраняет реальные ограничения архива и исходных данных. |
| 0:55–1:25 | Показать график, журнал агента и анализ | Агент проверяет источники и часы, запускает модель, проверяет границы мощности и рассчитывает сводку. При настроенном OpenAI/NVIDIA LLM объясняет результат через read-only инструменты, включая ветер по двум горизонтам; численные значения он не меняет. |
| 1:25–2:05 | Evidence → пять моделей → фильтры Turbine / Lead window → происхождение погоды → Download evidence | Медиана, климатология, persistence, SCADA и погодная модель оцениваются на одних и тех же парах выпуск/цель. Параметры выбраны до январского сравнения. Самая сильная простая модель не скрывается за слабым persistence. |
| 2:05–2:40 | Replay → архивная модель → Run February replay; показать CSV и manifest | 29 выпусков с 31 января по 28 февраля в 12:00 UTC; 48 часов на каждую турбину. Полный файл сохраняет все 2 784 точки, включая краевые часы января/марта; API-экспорт тестового периода фильтрует только февральские цели. Метрики пусты, поскольку фактов нет. |
| 2:40–3:00 | Показать refresh, README, `results/february-2026/manifest.json` | Каждый прогноз связан с моделью и неизменяемыми снимками; контрольные суммы, время доступности, параметры и ограничения можно проверить. |

Это план выступления, а не обещание времени вычисления. Если replay ещё выполняется,
показать его настоящий статус и заранее воспроизведённый артефакт. Не менять статус
происхождения ради демонстрации. Мощность нормализована на [0,1], а не выражена
в МВт; номиналы турбин и высота ступицы не предоставлены.

## Протокол времени и происхождения

- Обучение, валидация и февраль используют только циклы **00 UTC**, даже когда
  в исходном файле присутствуют дополнительные циклы.
- Ежедневный выпуск — **12:00 UTC**, то есть **17:00 гражданского времени
  Казахстана (UTC+5)** или **18:00 фиксированных часов исходной SCADA (UTC+6)**.
  При допущении публикации через 10 часов цели T+1…T+48 соответствуют лидам
  погодного цикла 13…60 и полностью покрыты архивом.
- Январская модель имеет cutoff **01.01.2026 00:00 UTC**. Выбор параметров
  использует ноябрь и декабрь 2025; январь — повторно использованный период
  сравнения, не нетронутый тест. Перекрывающиеся пары не независимы.
- Финальная модель имеет cutoff **31.01.2026 12:00 UTC**. Ей нельзя приписывать
  январские метрики более ранней модели. После окончания январской SCADA история
  стареет, без подстановки выдуманных февральских наблюдений.
- ECMWF-архив Open-Meteo включает IFS 49R1 hindcasts. Статус `verified` отдельного
  исследовательского импорта означает принятие документированного допущения,
  а не появление доказательства исторической публикации. API и worker продолжают
  возвращать новых кандидатов как `unverified`.

Источники расписания, единицы и полный разбор допущений:
[происхождение архива](weather-archive.md).

## Обновление погоды и повторный расчёт

Для существующего успешного прогноза:

```sh
uv run python -m wind_agent.worker --run-id run-REPLACE --once
uv run python -m wind_agent.worker --run-id run-REPLACE --once --fetch-run-init 2026-01-31T00:00:00Z
```

Во втором случае worker самостоятельно получает погодных кандидатов через API
по координатам турбин и явно заданному циклу. Сетевой источник может быть
недоступен; демонстрацию загрузки лучше подготовить заранее. Кандидат не получает
`verified` автоматически. Затем refresh сравнивает допустимые входы: неизменный
fingerprint даёт `changed=false`, изменившиеся допустимые входы запускают новый
расчёт. Получение непроверенного кандидата само по себе не меняет архивный прогноз.

Это законченный ограниченный цикл для указанного запуска. Автоматическое
обнаружение всех новых операционных циклов и независимое подтверждение их
публикации остаются направлениями развития.

## Вероятные вопросы

| Вопрос | Ответ |
| --- | --- |
| «Где здесь agentic AI?» | Агент получает/выбирает погоду, проверяет доступность и полноту, запускает модель, анализирует результат и пересчитывает изменившиеся входы. Необязательный LLM получает только рассчитанные сводки и не меняет мощность. |
| «Модель действительно использует погоду?» | Да: `weather-scada` получает ветер на 100 м, направление и температуру из выбранного архивного снимка. В Evidence отдельно показана SCADA-модель с теми же целями. |
| «Гарантировано ли, что эта погода была доступна тогда?» | Нет. Временные ограничения соблюдаются относительно явно принятого времени `run_init + 10h`, но hindcast и расписание не являются доказательством публикации каждого исторического выпуска. |
| «А простая константа?» | Медиана обучающей выборки и климатология включены в одинаковое сравнение. Если погодная модель проигрывает им в каком-либо разрезе, это видно в таблице; ничего не исключается после просмотра января. |
| «Почему DEMO / PROVISIONAL при реальном архиве?» | Общая метка охватывает синтетику и предварительные модели. В этом сценарии погода не синтетическая, но история и hindcast-доступность имеют указанные допущения. |
| «Где февральская точность?» | Февральских фактов нет. Есть почасовой прогноз и проверяемое происхождение его входов; февральские метрики не рассчитываются. |
| «Где веса?» | `npm run reproduce` обучает, сохраняет локальные веса и регистрирует финальную модель для API. Сохранённый JSON отчёта можно читать и без весов. |

Январские числа и все разрезы приведены в
[отчёте об обучении](tuned-training-results.md) и
[машиночитаемом исходнике](model-selection-results.json).

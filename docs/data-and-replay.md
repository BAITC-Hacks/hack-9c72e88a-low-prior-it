# Контракты времени и данных

Подтверждено владельцем проекта: координаты turbine-1 — 43.645139, 78.535611; turbine-2 — 43.643198, 78.538828. SCADA использует постоянный UTC+6 по максимальной корреляции с погодой, в том числе после смены гражданского времени. Мощность — доля номинала [0,1]. Номинальная мощность и высота ступицы не заданы условием. Время выпуска 07:00 UTC выбрано командой.

API принимает только время с явным часовым поясом и приводит к UTC. Метка наблюдения — конец часового интервала. Например, среднее исходных записей SCADA `2026-01-01 00:00..00:50` соответствует valid_time `2025-12-31T19:00:00Z`. Доступность наблюдения — этот конец плюс явно выбранная latency. Исходная интерпретация 10-минутных меток как начала интервала принята по прежнему коду; в исходном CSV описания меток нет.

```powershell
uv run python scripts/convert_scada.py --latency-minutes 60
uv run python scripts/import_csv.py data/canonical/observations.csv --name case-scada --provenance "Case SCADA; fixed UTC+6; interval ends; assumed 60-minute latency; stoppages preserved"
uv run python scripts/data_report.py
uv run python scripts/validate_models.py
```

60 минут — пример явного допущения для воспроизводимого baseline, а не доказанная задержка станции. Конвертер сохраняет `.metadata.json`. Минимум 4 валидные 10-минутные записи в часе. Физически недопустимые значения исключаются; допустимые простои сохраняются. Исходники неизменны. На текущих данных: 23 728 часов turbine-1 и 24 919 turbine-2; последнее значение заканчивается `2026-01-31T18:00Z`. Наблюдений за февраль нет.

Погодные времена различаются: `run_init` — инициализация модели; `available_at` — публикация; `retrieved_at` — скачивание. Архив без документированной публикации не допускается в replay. Полная матрица часовых значений сама по себе недостаточна. Для исходных compressed CSV можно выполнить `scripts/import_weather_archive.py`: они будут только unverified-кандидатами.

Forecast issued at T возвращает T+1…T+24/48, каждый timestamp — конец часа. Это rolling horizon, а не календарные сутки D+1/D+2. Не подменяйте эти протоколы: если организатор требует календарные сутки, нужно отдельно согласовать target window и API-контракт.

Replay принимает первый и последний issue, повторяет выпуск с шагом 24 часа, затем фильтрует target-окно `[start,end)`. Перекрытия сохраняются как самостоятельные issue/lead прогнозы. Модель фиксирована на весь replay; её cutoff не позже первого issue. Метрики per-turbine/per-horizon; агрегат MW отключён, потому что номиналы неизвестны.

Для демонстрации `scripts/smoke_demo.py` создаёт искусственный dataset/model, 48-часовой прогноз, refresh и 29 выпусков (31 января — 28 февраля UTC). Результаты `artifacts/february-demo.csv` и `artifacts/february-demo-report.json` помечены DEMO. Они не предназначены для конкурсной сдачи.
